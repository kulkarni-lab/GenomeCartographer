# Hox gene identification and phylogenetic analysis

This script is used to identify putative Hox genes from multiple peptide FASTA files, combining candidate sequences with reference Hox proteins, performing multiple sequence alignment and removing sequences that does not contain informative amino-acid residues after alignment. The program also reconstructs a phylogenetic tree using IQ-TREE.


## Requirements
Python 3.8 or newer
External programs required; `BLAST+` `MAFFT` `IQTREE2/3`

## Conda environment

Create a new conda environment:

`conda create -n hoxpull python=3.10` conda activate hoxpull

Install `BLAST+` `MAFFT` and `IQ-TREE`

```
conda install -c bioconda -c conda-forge blast mafft iqtree
```
Verify the versions of BLAST, MAFFT and IQ-TREE and also the path to IQ-TREE as the script requires the path to IQ-TREE.

`which iqtree` will show the path for the same

## Usage
The script accepts six command line arguments.

```
python3 1.Hox-multi-extract.py -p .pep_directory -r hox_references -i path_to_iq-tree -o outdir -t threads -e e-value -m max-targets
```
`-p` path to directory containing all peptides
`-r` reference hox peptides .fasta
`-i` path to IQ-TREE executable
`-o` output directory
`-t` number of CPU threads
`-e` BLASTP E-value threshold
`-m` Maximum blast target sequences


# Input files

The pipeline requires two input files.

## 1. Reference Hox protein FASTA 
`-r` 

Example: `ref_hox_peps.fasta`

This file contains known/reference Hox proteins. This reference will be used as BLASTP queries against each species peptide fasta.

## 2. Species peptide FASTA files
`-p`
The directory can contain `.fa` `.faa.` `.fasta` 
```
Example: peps/
         species_A.fa
         species_B.fasta
         species_C.faa
         species_D.fa
```

The species name is extracted from the filename: `species = os.path.basename(quert_fasta_).split(".")[0]`

Therefor:
`Species_A.fa` becomes `Species_A`

- This name will be added as prefix to candidate sequence IDs.

Example: >XP_12547 becomes Species_A|XP_12547


# Output

The output directory `-o HoxTree` will have multiple files including:
```
all_candidate_hox.fa
hox_alignment.fa
hox_alignment.cleaned.fa
tmp
iqtree_run
```

### Output files description

**1** `all_candidate_hox.fa`

- This fasta file contains the reference and the putative Hox proteins, which will be handy for checking which candidates were identified.

**2** `hox_alignment.fa`

- This is the raw MAFFT multiple sequence alignment, this file contains all sequences before gap-only sequence removal.

**3** `hox_alignment.cleaned.fa`

- Alignment after removing the sequences containing no usable residues. This is the alignment supplied to IQ-TREE.

**4** `tmp`

- Inside this directory there will be temporary files created for running the program, like:
```
species_A.blast.tsv
species_A_db.pdb
species_A_db.phr
species_A_db.pin
species_A_db.pjs
species_A_db.pot
species_A_db.psq
species_A_db.ptf
species_A_db.pto
species_B....
```

**5** `iqtree_run`

- Inside this directory there will be files related to IQ-TREE, such as:
```
hox.bionj
hox.ckp.gz
hox.iqtree
hox.log
hox.mldist
hox.treefile
hox.uniqueseq.phy
```

- `hox.treefile` is the main phylogenetic tree generated by IQ-TREE. This tree can be used for visualization using FigTree, iTOL etc.


## Workflow of the script

#### Step 1 — Dependency Checks
 -The script first checks for:
```
makeblastdb
blastp
mafft
```
using: `which()`
- If any dependency is missing, the script terminates with an error.
- IQ-TREE is checked separately using the path supplied by: `-i

#### Step 2 — Create Output Directories
- Three directories are created:
```
HoxTree/
HoxTree/tmp/
HoxTree/iqtree_run/
```
- The temporary directory contains BLAST databases and BLAST output.
- The IQ-TREE directory contains the phylogenetic analysis files.

#### Step 3 — Find Peptide FASTA Files
- The script searches the peptide directory for: `*.fa,` `*.faa,` `*.fasta`
- All matching files are sorted before processing.

#### Step 4 — Build BLAST Protein Databases

- For every species, the script runs:
```
makeblastdb \
    -in Species_A.faa \
    -dbtype prot \
    -out HoxTree/tmp/Species_A_db
```
- This converts the peptide FASTA into a searchable local BLAST protein database.

#### Step 5 — BLASTP Search

- The reference Hox proteins are searched against each species' proteome.

Conceptually:

Reference Hox proteins
        │
        │ BLASTP
        ▼
Species proteome
        │
        ▼
Similar proteins

The command uses: `-outfmt 6` with the following fields:
```
qseqid
sseqid
pident
length
evalue
bitscore
```

- The script ultimately uses the sseqid field to identify candidate proteins.

#### Step 6 — Candidate Extraction

- The script reads the BLAST output and collects unique subject IDs.

For each candidate:
```
Original: >protein123

the script generates:

>Species_A|protein123
```
- This prevents sequence-ID collisions between species.

#### Step 7 — Combine Reference and Candidate Proteins

- The output: `all_candidate_hox.fa`
```
contains:

Reference Hox proteins
Candidate Hox proteins from Species A
Candidate Hox proteins from Species B
Candidate Hox proteins from Species C
etc.
```
[NOTE!]The reference sequences are written first.

#### Step 8 — MAFFT Alignment

- The combined FASTA is aligned using:
```
mafft \
    --auto \
    --thread 29 \
    all_candidate_hox.fa
```
- The output is: `hox_alignment.fa`

- MAFFT attempts to place homologous amino-acid positions into the same alignment columns.

Conceptually:
```
Hox_A    MAAA--KKLLVV
Hox_B    MAAAT-KKLLVV
Hox_C    M-AAT-KKLVVV
             ↑
       homologous sites
```
- The alignment is the foundation for phylogenetic inference.

#### Step 9 — Remove Gap-Only Sequences

- The script creates: `hox_alignment.cleaned.fa`

- Sequences are removed if, after removing: `- ? N X *` 

- This protects the phylogenetic analysis from sequences that contain no usable information.

- The script reports removed sequences:

[NOTE!] Removed gap-only sequences:
  - Species_A|candidate123
- Important Interpretation of Sequence Cleaning
- The script removes entire sequences, not alignment columns.

```
For example:

>Candidate_A
----------------------

will be removed.

However, a sequence such as:

>Candidate_B
M---A---K-----------

is retained because it contains usable residues.
```

#### Step 10 — IQ-TREE Phylogenetic Reconstruction

- IQ-TREE is run using: `-m Q.INSECT+F+G4`

- The model therefore specifies: `Q.INSECT` with: `+F` empirical amino-acid frequencies, and: `+G4` a four-category discrete gamma model for among-site rate variation.

The command is effectively:
```
iqtree3 \
    -s hox_alignment.cleaned.fa \
    -m Q.INSECT+F+G4 \
    -nt 29 \
    -pre HoxTree/iqtree_run/hox
```
### IQ-TREE Model

The script currently uses: `Q.INSECT+F+G4`
- This is an amino-acid substitution model implemented by IQ-TREE and intended for insect protein evolution.
- If your dataset consists primarily of mites/ticks or other Acari, you should critically evaluate whether Q.INSECT+F+G4 is the most appropriate model for your dataset.
- The model is inherited from the script's current configuration and should not automatically be treated as optimal simply because it is used in the pipeline.

- A useful improvement for a production analysis is to allow IQ-TREE to perform model selection, for example: `-m MFP` or an appropriate amino-acid model-selection workflow.

- This should be considered separately from the current script because changing the model changes the analysis.

#### Bootstrap and SH-aLRT

- The script currently contains: `# "-bb", "1000",` `# "-alrt", "1000",`

- These lines are commented out. Therefore, the current script does not request ultrafast bootstrap or SH-aLRT support values.

- If you uncomment: `-bb 1000` `-alrt 1000` IQ-TREE will calculate additional branch-support measures.
